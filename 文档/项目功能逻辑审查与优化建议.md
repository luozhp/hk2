# 项目功能逻辑审查与优化建议

> 审查范围:`hunter/server`（16 个业务模块）+ `hunter/web`（16 个页面 + 路由/store/api 封装/布局）。
> 方法：全量通读源码，并对照项目文档（产品功能文档 / 架构文档 / README）核对口径。
> 产出：功能地图 + 分级问题清单 + 分阶段优化路线。
> 审查日期：2026-09-11。

---

## 一、结论摘要

**总体成熟度**：架构清晰、注释到位、核心闭环（采集 → 线索 → 客户 → 邮件 → 询盘 → 看板 → 维护）已打通。新写的复杂页（维护台账、海关导入、行业平台）错误处理与交互完成度较高；早期页（线索/客户/采集）存在模式滞后。

**三大最高风险（建议立即处理）**
1. **数据安全后门**：`POST /api/reset` 完全公开，未登录即可清空整库并恢复种子数据（`app.controller.ts:15`）；登录页还硬编码演示账号密码（`web/Login.vue:57`）。
2. **认证/授权形同虚设**：`JWT_SECRET` 仍是占位值（`server/.env:5`，默认 `hunter-dev-secret-...`），可伪造任意 admin token；RBAC 只在用户管理接口生效，其余接口任何登录角色（含业务员）都可改任意数据、改系统配置、读站点密钥（`settings` 无 `@Roles` 且下发 `siteKey`）。
3. **邮件真实发送链路不可用**：附件 `path` 取自 `complianceDocs.publicLink`（如 `/docs/msds`，非真实文件路径/URL），真实 SMTP 通道下带附件邮件必失败；且可被指向本地文件，形成服务器文件外泄通道（`mail.module.ts:144`、`compliance` PUT 未做校验）。

**三大最高收益（花小钱办大事）**
1. 修复 **日限额批量绕过**（剩 1 封额度可一次发 100 封，`mail.module.ts:101`）与 **Census 累计值重复累加**（结果放大约 N 倍，`customs.module.ts:259`）。
2. 统一 **持久层与校验**：引入 DTO + ValidationPipe；持久层从"整库 JSON 重写"改为真实表或增量写（当前每次小操作都整库落盘，无引用完整性，是最大写放大与损坏面）。
3. 抽取三个公共层即可消除约 60% 的重复/不一致：**搜索/评分/导入公共逻辑**（现 3-4 处逐字重复）、前端 **useList(分页/loading/竞态)+ useConfirm + dict 工具**、统一 **错误响应与日期口径**。

## 二、系统功能地图

### 2.1 后端模块（`server/src`，16 个）

| 模块 | 职责 | 关键路由 |
|---|---|---|
| auth / db | JWT 登录、成员管理（bcrypt）、SQLite 持久化 | `/auth/*` |
| discover | 线索采集（Google CSE/SerpAPI/mock、三标准打分） | `/discover/*` |
| leads | 线索池（筛选/评分/录入/导入/转客户） | `/leads/*` |
| customs / directory / expo | 海关数据、行业平台、展会（导入/检索转线索） | `/customs/*` `/directory/*` `/expo/*` |
| companies | 客户 360（客户/联系人/跟进/商机） | `/companies/*` |
| mail | 开发信（模板/禁词/限额/发送/追踪/收信） | `/mail/*` |
| compliance | 合规文档库 / 禁词库 / 文案扫描 / 检查清单 | `/compliance/*` |
| keywords / landing | 关键词库、落地页清单 | `/keywords/*` `/landing-pages` |
| inquiries | 询盘管理与归因 + 独立站公开回传 | `/inquiries/*`、`POST /public/inquiry` |
| analytics / dashboard | 漏斗/渠道/KPI、工作台总览 | `/analytics/*`、`/dashboard/overview` |
| maintenance | 客户维护档案 + 跟进动态 | `/maintenance/*` |
| settings | 系统配置（siteUrl/brandName/siteKey 等） | `/settings` |

### 2.2 前端页面（`web/src/views`，16 个）

工作台 Dashboard、线索采集 Discover、线索池 Leads、询盘 Inquiries、客户 Customers、客户详情 CustomerDetail、客户维护 Maintenance、邮件中心 MailCenter、合规 Compliance、关键词库 Keywords、获客渠道 Channels、海关数据 CustomsData、行业平台 Directory、国际展会 Expos、数据看板 Analytics、系统设置 Settings；外加登录 Login。

### 2.3 核心数据流

```
discover / customs / directory / expo（采集或导入）
   → leads（score/grade/三标准）
   → /leads/:id/convert → companies（+contacts/activities/opportunities）
   → mail（模板渲染→禁词拦截→日限额→SMTP/mock→mailRecords；IMAP/webhook/追踪像素回写）
   → 客户回信 mailReplies 与 inquiries（独立站 /public/inquiry 回传，带 sourceChannel 归因）
   → analytics / dashboard 统计收口；成交后 maintenance 做复购/跟进维护
```
