## 2. 建设目标与设计原则

### 2.1 建设目标

| 维度 | 目标 |
|---|---|
| 业务目标 | 支撑"线索 500+、询盘 100+/年、开发信回复率 ≥3%"的 2026 目标，并可扩展至 2028 规模 |
| 技术目标 | 轻量、低成本起步，核心链路 2-3 个月可上线 MVP |
| 运维目标 | 团队无专职运维前提下，可稳定运行、可备份、可回滚 |

### 2.2 设计原则

| 原则 | 说明 |
|---|---|
| MVP 优先 | 先跑通"采集→筛选→发信→跟进→看板"主链路，非核心功能后置 |
| 模块化 | 按 PRD 的 A-J 模块独立划分，可独立迭代 |
| 集成先行 | 邮件、Google、CSV 导入等第三方能力优先用成熟服务，不重复造轮子 |
| 合规内建 | 禁词扫描、频控、退订、审计在设计层内建，非后期补丁 |
| 成本可控 | 起步用单体+单云数据库，达规模再拆分；避免过早微服务化 |

## 4. 部署形态选型

| 方案 | 说明 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **A. 全自研自建** | 前后端+数据库全部自建部署 | 数据自主、可定制、长期成本可控 | 开发周期长、需基础运维能力 | ⭐ **推荐（MVP）** |
| B. SaaS 采购改造 | 采购外贸 CRM + 邮件工具组合 | 上线快 | 线索模型/合规功能定制受限、按坐席收费 | 可作对比评估 |
| C. 混合 | 自研核心 + SaaS 邮件/地图 | 兼顾速度与定制 | 集成复杂度高 | 不推荐首期 |

> **结论**：采用 **方案 A 自研自建**，理由：
> 1. 三标准校验、禁词扫描、频控策略是**业务差异化能力**，SaaS 无法满足；
> 2. 数据（客户邮箱、海关线索）敏感，自主可控更安全；
> 3. 技术栈开源成本低，无坐席费，长期总成本更优。

## 5. 技术选型对比与建议

### 5.1 前端

| 方案 | 优点 | 缺点 | 评估 |
|---|---|---|---|
| **Vue 3 + Element Plus** | 中文生态成熟、学习成本低、后台型组件全 | — | ⭐ **推荐** |
| React + Ant Design | 生态最大、招人容易 | 上手曲线略陡 | 备选 |
| Next.js / Nuxt | SSR 利于 SEO | 本项目为内部工具，无 SEO 需求 | 不必要 |

> 内部管理系统，**Vue 3 + Element Plus + Vite**，移动端核心页用 H5 适配。

### 5.2 后端

| 方案 | 优点 | 缺点 | 评估 |
|---|---|---|---|
| **NestJS（Node/TypeScript）** | 与前端同语言、模块化结构贴合 PRD 模块、异步处理强 | 高并发逊于 Go/Java | ⭐ **推荐** |
| Spring Boot（Java） | 企业级成熟 | 重、开发慢、成本高 | 团队无 Java 背景则不选 |
| Python FastAPI/Django | 爬虫/数据处理生态好 | 长链路稳定性一般 | 备选（若团队偏 Python） |

> 邮件异步、Google 接口、Excel 解析在 Node 生态均有成熟库，且前后端同栈降低维护成本，推荐 **NestJS**。

### 5.3 数据库

| 方案 | 优点 | 缺点 | 评估 |
|---|---|---|---|
| **PostgreSQL** | 关系模型强、JSONB 灵活、扩展性强 | — | ⭐ **推荐** |
| MySQL | 主流易运维 | JSON 能力弱于 PG | 可接受 |
| MongoDB | 文档模型 | 关系查询（商机/客户/邮件）复杂 | 不推荐 |

> 线索、客户、邮件、商机强关联，PRD 数据模型以关系为主，选 **PostgreSQL 15+**。

### 5.4 缓存与队列

| 组件 | 用途 | 建议 |
|---|---|---|
| Redis | 会话、频控计数、队列、缓存 | ✅ |
| BullMQ（Node） | 邮件批量发送队列、定时任务 | ✅ 与 NestJS 集成好 |

### 5.5 邮件服务

| 方案 | 优点 | 缺点 | 评估 |
|---|---|---|---|
| **Amazon SES** | 极低价格（$0.10/千封）、信誉机制成熟 | 需配置 DKIM/SPF | ⭐ **推荐（正式发送）** |
| SendGrid | 国内可用性好、统计完善 | 免费额度限制、价格略高 | 备选 |
| 自有 SMTP（企业邮箱） | 零额外成本 | 发信量受限、易进垃圾箱 | 仅用于小批量/预览 |

> 发送前域名预热 + SPF/DKIM/DMARC 配置，配合系统频控策略。

### 5.6 部署与运维

| 项 | 建议 |
|---|---|
| 云厂商 | 腾讯云 / 阿里云（国内团队运维方便），或 AWS（若已用） |
| 容器 | Docker + Docker Compose（单机），后续可迁 K8s |
| CI/CD | GitHub Actions / 云效，自动构建部署 |
| 监控 | 日志 + 简单告警（云监控即可），后期 Prometheus |
| 备份 | RDS 自动备份 + 每日对象存储备份 |

### 5.7 技术栈总览（推荐组合）

```
前端：Vue 3 + TypeScript + Vite + Element Plus + Pinia + ECharts(看板)
后端：NestJS + TypeScript + Prisma(TypeORM) + BullMQ + JWT
数据库：PostgreSQL 15 + Redis 7
存储：云 OSS/S3（合规文档、附件）
邮件：Amazon SES（正式）+ 自有 SMTP（测试预览）
集成：Google Search/Ads/Maps API、IMAP 收件、LinkedIn（V1.2）
部署：Docker Compose + 云主机(2C4G) + 云托管 PG
```

## 6. 关键集成方案

### 6.1 Google 生态

| 集成 | 方案 | 说明 |
|---|---|---|
| 搜索结果线索 | **Custom Search JSON API**（官方，100 次/天免费，超限按 $5/千次） | 合规采集，替代爬虫；免费额度可支撑 MVP 线索量 |
| Google Maps 校验 | Maps API Place Search | 三标准之一"地图可定位"自动校验 |
| Google Ads | Ads API 或手动导入（V1.1 后 API） | 前期 CSV 导入够用 |
| 排名跟踪 | 第三方（如 SerpApi）或自建定时查询 | V2.0 再做 |

### 6.2 邮件收发

- **发送**：SES API + 模板变量渲染；发送队列走 BullMQ；频控（每账号日 50 封、间隔随机 60-120s、多账号轮换）。
- **接收/回复识别**：IMAP 轮询收件箱，按 Message-ID 关联回复到对应联系人，同步客户时间线。

### 6.3 海关数据

- 一期：ImportGenius / Panjiva 导出 Excel → 系统导入（字段映射）。
- 二期：按供应商提供的 API 对接（需评估预算）。

### 6.4 独立站询盘

- 独立站表单增加 webhook/API 提交至系统；或邮件接入自动建档。
- 询盘查重（邮箱/域名）自动归属。

### 6.5 第三方文件与导入

- 统一使用 `exceljs`（Node）解析/生成 Excel，字段映射界面化。

## 8. 核心流程原型

### 8.1 主动开发全流程（线框流程）

```
[线索采集页]
  执行预置语法 → 结果勾选 → [校验并入库]
        ↓
[线索池]
  评分/筛选 → [批量转客户]
        ↓
[客户详情]
  [添加决策人](LinkedIn) → [记录跟进]
        ↓
[邮件发送中心]
  选客户+模板 → 检查(禁词/合规/频控) → [发送]
        ↓
[发送记录→客户时间线]
  IMAP 收到回复 → 自动标记 → 工作台"未读回复"提醒
        ↓
[商机]
  询盘→寄样→报价→谈判→成交(复购提醒)
```

### 8.2 被动获客接入流程

```
独立站询盘(webhook/邮件) → 询盘中心 → 查重:
  ├─ 新客: 自动建客户档案 → 分配业务员 → 24h SLA 计时
  └─ 老客: 挂接到现有客户 → 时间线记录来源渠道
之后广告/SEO 数据 → 询盘归因(来源关键词/落地页) → 看板
```

## 9. 安全与合规设计

| 类别 | 设计 |
|---|---|
| 认证 | JWT + 刷新令牌；密码 bcrypt；登录限流 |
| 权限 | 按 PRD §7 权限矩阵，后端接口级鉴权 |
| 数据安全 | 全站 HTTPS；客户邮箱/电话字段加密存储；导出需权限+审计 |
| 邮件合规 | 退订即移除（CAN-SPAM）；真实发件信息；SPF/DKIM/DMARC 配置 |
| 内容合规 | 禁词库全局扫描：邮件发送阻断、落地页/广告文案检查 |
| 审计 | 导出、删除、发送、权限变更全量记录 |
| 备份 | 数据库每日备份+保留30天；对象存储版本管理 |

## 10. 实施计划与里程碑

| 阶段 | 时间 | 交付物 | 关键点 |
|---|---|---|---|
| M1 设计与初始化 | 2 周 | 架构评审、项目脚手架、CI/CD、数据库迁移脚本 | 决策点：技术栈冻结 |

## 12. 风险与决策点

### 12.1 技术风险

| 风险 | 应对 |
|---|---|
| Google API 免费额度不足 | 额度内精确关键词；不足时控制采集频次或购买配额 |
| 邮件域名信誉被污染 | 预热 + 频控 + 独立发送子域 + 监控回弹率 |
| 集成授权变更（Google/LinkedIn） | 关注政策，预留手动导入兜底 |
| 单机部署性能瓶颈 | 起步量小无虞；预留迁移容器编排路径 |

### 12.2 决策点（待管理层确认）

1. **技术栈是否采用 Node/Vue 全栈**（若团队另有 Java/Python 背景则调整）；
2. **邮件正式发送是否接入 SES**（需 AWS 账号）还是 SendGrid；
3. **MVP 是否纳入海关数据导入**（建议纳入，方式为 Excel 导入）；
4. **是否需要移动端 App**（建议 H5 适配即可，不单独做 App）；
5. **预算上限**：确认云资源与工具订阅预算，用于最终选型。
